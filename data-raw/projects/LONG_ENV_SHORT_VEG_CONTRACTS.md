# Long environment and short vegetation report contracts

Review date: 2026-09-23. These are **data-contract reviews**, not implementations or approvals of all legacy UI/Excel behavior. Canonical source: `../VPRO_ACCESS/VPro64_forAI/Modules/V7mdlReportsEnv.txt` (`EnvReport`) and `V7mdlReportsShortVeg.txt` (`NewShortVeg`, `MakeSvQueries`), with `V7mdlCreateTables.txt` (`CreateTempVeg`). Existing QMDs are `inst/app/reports/long_env.qmd` and `short_veg.qmd`.

## Long environment: Access contract

**Scope and unit membership.** Require an attached, active SU. Enumerate non-null `SiteUnit` labels among SU rows with non-null `PlotNumber`, independent of the Env `UserSiteUnit` and `SiteSeries` fields (`V7mdlReportsEnv.txt:17-33`). For each unit, use its SU memberships with the active project's joined Env/Admin fields. The Access SQL is `USysEnv RIGHT JOIN <current>_SU` filtered to that unit (`:61-70`); a membership with no matching Env/Admin still contributes a row with null environmental columns. The existing `vpro_report_environment()` reads `USysEnv`, which removes duplicate membership rows and excludes orphan SU memberships: it is a useful field source, **not** sufficient for this report's full join contract. Treat repeated SU rows and multiple master-list matches explicitly rather than silently multiplying/dropping them. A future API should return structured `SiteUnit`, plot/membership identity, and projected field/value data without writing to source databases.

**Unit title.** `MasterSiteUnitList` is left-joined on `SU.SiteUnit = MasterSiteUnitList.SiteSeries`, using `First(SiteSeriesLongName)` and no `Level = 11` restriction (`V7mdlReportsEnv.txt:25-33`; `data-raw/lists/MasterSiteUnitList.sql:1-7`). Do not substitute `vpro_assigned_site_units(source = "master")`: that API filters to level 11. Because Access `First()` is undefined for multiple matching names, a deterministic conflict policy or an explicit ambiguity diagnostic is required before adding a name-enrichment API.

**Projection.** The *live* Access SELECT (`V7mdlReportsEnv.txt:61-67`) is authoritative, rather than its preceding commented-out version. In exact field order, map the source fields below to display labels where shown. All unannotated fields retain their source name; `(heading)` is an output row containing nulls, not a source column. `SitePlotQuality` and `HumusThickness` are Admin fields; read the joined Env/Admin source (`R/project-context.R:384-389`), not physical Env alone.

**Presentation boundary.** Access writes one Excel worksheet per unit, transposes the projected table to field rows and plot columns (`:70-85`), names each sheet after the SU code using `SheetNameCheck`, then sorts sheet names case-insensitively (`:167-208`). No SQL plot ordering is specified: a future deterministic plot order is a modernization, not verified Access parity. Keep headings as explicit typed metadata rather than injecting null pseudo-columns into SQL. The QMD instead reads `Sample_Env`, joins raw SU/master names and prints plot rows in HTML (`long_env.qmd:95-130,216-257,264-272`); it cannot supply Admin-only fields from its current source, may multiply rows on master-name matches, and is not a drop-in implementation of this contract. QMD `SiteNotes` and its plot/project fallbacks are additional, not Access `EnvReport` fields/scope.

**Long-Env output policy (modernization decision, 2026-09-23).** A future data API should start with eligible physical SU rows (`PlotNumber` and `SiteUnit` non-null), left join physical project Env then Admin, and return membership `PlotNumber` separately from projected `USysEnv.PlotNumber` (Access's projected `Plot` is null for an unmatched join). Distinguish `missing_env` (no Env) from `missing_admin` (Env exists but Admin does not); both appear in the unit's report as a plot column headed by **SU membership PlotNumber**, with empty environmental values and a visible `Missing Env` or `Missing Admin` status. Do not fabricate Env/Admin values or silently omit these plots. This visible membership label is an intentional difference from the Access `RIGHT JOIN` field projection. A repeated identical `(SiteUnit, PlotNumber)` membership appears once in presentation with a `duplicate_membership_count` diagnostic recording the source count; different units retain their own columns. Sort units by case-folded code with exact-code tie break, plots by plot number with exact-code tie break; this is deterministic, not claimed to match Access's unspecified within-sheet plot order.

For unit titles, join every `MasterSiteUnitList` row on `SiteSeries` without a level filter. One distinct nonempty `SiteSeriesLongName` yields the title even if other matching rows have null/empty names; zero names falls back to the unit code with `missing_unit_name` status. More than one distinct nonempty name falls back to the unit code with `conflicting_unit_names` status and the sorted candidate names in diagnostics. Do not pick Access's row-order-dependent `First()` or duplicate the report on a one-to-many master join. Comparison of names is exact after excluding null/empty strings; trim/case normalization of nonempty names requires separate approval. A renderer must show statuses alongside output, not hide them in logs. Excel-specific sheet-name collisions and output-format decisions remain open. Test orphan Env/Admin, duplicate memberships, repeated/contradictory master entries, empty-unit results and source immutability before implementing. No changes to `vpro_report_environment()` or `long_env.qmd` follow solely from this decision.

## Short vegetation: proposed SU-scoped package contract

**Separate the two existing behaviors.** Access `NewShortVeg` refuses to run without a current SU and calls `QC` before assembling temporary membership (`V7mdlReportsShortVeg.txt:380-416,476-487`). The old `short_veg.qmd` permits explicit plot-number and project-ID fallbacks, which take precedence over its `site_unit` option; it pools all selected plots into one summary (`short_veg.qmd:7-26,83-103`; `_TO_CLASSIFY/R/logic_reports_veg.R:127-160,251-295`). It neither calls QC nor produces Access's per-unit pivot. Its default `avg_type = "mean"` means by-n-plots inside that helper (`logic_reports_veg.R:260-269`). Therefore an API claiming Access short-report parity must **not** simply wrap `summarize_veg_report()` or project-wide `vpro_report_all_veg()`.

**Input and selection proposal.** Require an active project and active SU; use the quality-filter default and explicit reference paths specified below, while allowing the caller to override filtering settings. Preserve `(PlotNumber, SiteUnit)` membership in the active SU; when quality filtering is enabled, apply `vpro_filter_plot_quality()` and use its `selected` pairs, including the short-report BEC option (`R/report-quality.R:277-320,339-419`). Do not mutate the current SU. Collapse duplicate `(SiteUnit, PlotNumber)` memberships for summary calculations under the denominator policy below; report duplicate counts diagnostically. Blank/null unit eligibility remains unresolved; quality-filter settings and `bec_min` must remain parameters rather than inferred from historical registry state. With QC disabled, use the active SU membership as-is, not the `USysEnv` view (which loses orphan and duplicate membership information). An explicit plot filter should be an *intersection* with selected membership for this new contract, never a way to bypass SU membership.

**Vegetation and aggregation proposal.** For each selected plot, read the physical project Veg table. The Access `CreateTempVeg` groups by `(PlotNumber, Species)` and takes the maximum **separately for each cover field** across duplicates (`V7mdlCreateTables.txt:371-396`), before `BuildDataTable` and optional lumping (`V7mdlReportsShortVeg.txt:1230-1234,1509-1526`). Preserve the original layer mappings and species labels; `vpro_report_all_veg()` offers the saved-query distinct `UNION` over layers 1–7, 5a–5c, A and B, but is project-wide and does not perform this max-by-field consolidation (`R/report-all-veg.R:3-50`). The Access crosstab groups by layer/strata/lifeform/none and species, pivots a column **per site unit**, filters `CodeType = 'S'` while keeping null metadata, and draws scientific/common labels from `USysAllSpecies`, not necessarily `USysAllSpecs` (`V7mdlReportsShortVeg.txt:1240-1299,1403-1468`). Implementing against canonical VLists requires an explicit comparison of these reference views and layer metadata; the retired QMD's joins are not established parity.

**Numeric core and output shape.** At minimum a package-native *long* result should have `SiteUnit`, `group`, `species_code`, `species_label`, optional `common_label`, `n_plots_unit`, `n_cover_records`, `sum_cover`, `presence_ratio`, `mean_cover`, and derived `display_value`; a renderer can pivot units to columns. For a given unit/group/species, Access constructs `nPlots = Count(SU.PlotNumber)` in `SV1` and `MyCover` from `Count(Cover)/First(nPlots)`, `Sum(Cover)/First(nPlots)` (by-n-plots), or `Avg(Cover)` (characteristic) (`V7mdlReportsShortVeg.txt:1356-1396,1448-1468`). A disposable DAO scratch probe of the reconstructed `CreateTempVeg`/`SnTable`/`SV1`/`SV2` stages found that `nPlots` is a count of SU membership **rows**, while `Count(Cover)` is a count of joined non-null cover **rows**, not distinct plots. With P1 cover maxima 15 (source values 10 and 15), P2 cover 5, and P3 without Veg, the baseline U membership (P1, P2, P3) produced 3 denominator rows, 2 cover rows, presence 2/3, and by-n-plots cover 20/3. Duplicating P1/U yielded 4 denominator rows, 3 cover rows, presence 3/4, by-n-plots cover 35/4, and characteristic mean 35/3. Adding P1/V and P3/V instead left U unchanged and gave V presence 1/2 and by-n-plots cover 15/2. Evidence and reproducible runner: `data-raw/oracle/short-veg-denominator-oracle.json` and `data-raw/oracle/run-short-veg-denominator-probe.ps1`. The original front-end SHA-256 was identical before and after. This probes Access DAO SQL mechanics on scratch tables, **not execution of `NewShortVeg`, its QC flow, full layer expansion, or Excel output**; avoid labeling a plot-level distinct presence ratio as Access parity. Document zero covers as counted non-null values unless evidence overturns that rule. Return typed numeric aggregates before presentation/classification; a QMD display column should not be the sole calculation output. Include empty units and zero-denominator behavior explicitly in an implementation design.

**Options and unsettled parity.** Grouping: layer, strata, lifeform, none; ordering: species or value, plus an explicitly reviewed presence ordering if retained from the QMD. Averaging: by-n-plots versus characteristic. Display: presence/mean, presence/significance, rk, prominence, Goldstream, and cover, with separate constancy and common-name options (`V7mdlReportsShortVeg.txt:1246-1299,1356-1422`; `short_veg.qmd:11-20,124-155`). Existing value conversion functions can support parts of display formatting, not crosstab calculations. QMD `presence_min` and `cover_min` are inclusive and its positive `value_limit` uses strict `>` only for value ordering (`logic_reports_veg.R:344-369`); confirm Access option semantics separately. Access lumping caps sums at 99 (`V7mdlLumping.txt:54-84`), whereas the retired QMD sums uncapped. The scratch DAO probe establishes a limited denominator/join result, not full Access numeric output or source-to-output parity. The proposed package summary uses unique-plot denominators as specified below. Quality defaults, metadata conflict handling and opt-in lumping are decided below; verify reference coverage, grouping mappings, option-specific output and controlled numeric fixtures before implementing or claiming Access parity. Do not label the modernized calculations as Access parity.

**Denominator policy (modernization decision, 2026-09-23).** For a new package-native short-vegetation summary, count distinct eligible `PlotNumber` values *within each `SiteUnit`* after selection/quality filtering. Collapse repeated `(SiteUnit, PlotNumber)` rows before joining consolidated per-plot vegetation, so each eligible plot contributes at most once per unit to both numerator and denominator; a plot assigned to different units contributes once to each. The presence numerator is the number of distinct eligible plots with a non-null consolidated cover for the particular group/species; a cover of zero is non-null and counts. By-n-plots cover divides the sum of those per-plot cover values by the unique eligible plot count, including eligible plots without vegetation in the denominator. Characteristic cover averages the non-null per-plot values. Return duplicate membership counts and denominator values as diagnostics; do not silently drop the evidence of duplicates. For a unit with zero eligible plots, return no species aggregates and report the empty unit explicitly rather than divide by zero. This policy avoids accidental over-weighting caused by duplicate SU rows and is **intentionally different** from the Access `SV1`/`SV2` membership-weighted SQL established by the scratch probe (for example, duplicate P1/U yields 2/3 presence and 20/3 by-n-plots cover here, versus Access's 3/4 and 35/4). It is not an approval of a full short-report implementation or a claim of Access output parity. Preserve the observed Access-weighted formulas in evidence for any separately named compatibility mode, which would require explicit approval and end-to-end validation before use.

**Quality-filter default (package decision, 2026-09-23).** Default `enforce_quality = FALSE` in the *new short-vegetation API*, matching the unset Access registry's `DataQualityFilterEnforce = False` (`clsRepOpt.txt:481-486`), not inheriting `vpro_filter_plot_quality()`'s current `enforce = TRUE` default (`R/report-quality.R:308-319`). An unenforced run keeps eligible active-SU membership, subject to the explicit denominator and unit-eligibility policies; never infer a user's historical registry values. Expose an explicit switch and, when enabled, pass explicit Site/Veg/Soil minima (default `Poor`), missing-quality inclusion flags (default `TRUE`), optional `bec_min` (default `NULL`, so no BEC cutoff), and missing-BEC inclusion flag (default `TRUE`) to `vpro_filter_plot_quality()`. Filtering may remove incomplete Env/Admin project plots; return removal diagnostics, and do not mutate the current SU. An unset Access BEC-minimum registry value of `"True"` is not a meaningful cutoff and must not be imported as one. The API should expose in its result whether filtering ran, so an unfiltered report cannot be mistaken for quality-vetted output. This chooses a safe non-dropping default, not reproduction of a previously customized Access installation.

**Species metadata rule (package decision, 2026-09-23).** Use explicit read-only `VLists.db` (`USysAllSpecs`) and `VUser.db` (`USysUserSpp`) reference paths; derive the five-field `USysAllSpecies`-style union (`Code`, `ScientificName`, `LifeForm`, `EnglishName`, `Codetype`) with case-insensitive exclusion of `Codetype = 's'`, as in `Queries/USysAllSpecies.txt:1-4`. Do not substitute `USysAllSpecs` alone or the `USysSppAttributes` table. Collapse exact five-field duplicate rows as Access `UNION` does, then match code without silently multiplying vegetation rows. The bundled master/reference union has 35 case-insensitive code keys with conflicting five-field metadata; two (`ANEMRIC`, `CAMPHIP`) occur in the bundled Sample Veg. For **used** conflicting codes, fail with a sorted, actionable conflict list unless a caller supplies an explicit reviewed one-record-per-code resolution; do not pick `First()`, a preferred source, or a row by physical order. Missing lookup codes remain in output with their original species code as label, null scientific/common/lifeform metadata and an `unmatched_code` diagnostic (the Access left join retains them). A unique metadata row can have a missing English name or LifeForm: keep it, show the missing field, and mark metadata incompleteness separately rather than treating optional common names as lookup failure. Keep raw species code as the grouping key even if scientific labels coincide. Lifeform grouping requires nonmissing, unambiguous species LifeForm; report unresolved/missing group assignments explicitly rather than silently dropping cover. A disposable DAO query-stage oracle verified the copied Access `LayerCode` join for layer/strata rows but not a package SQLite replacement; see `SHORT_VEG_LAYER_STRATA_ORACLE.md`. A validated versioned mapping must be supplied or bundled before implementing those grouping modes. This rule does not alter the existing `vpro_validate_vegetation_codes()` master-only validation contract.

**Lumping rule (package decision, 2026-09-23).** Default to **no lumping**. If the caller explicitly selects a lump table, apply it *after* per-plot/per-species per-field maximum consolidation and layer/strata/lifeform/none transformation, as `BuildDataTable` does (`V7mdlReportsShortVeg.txt:1509-1525`), but before unit aggregation. Read only mappings with `Use = Yes`; unmapped species retain their source code. Require a single nonempty target per active source code, reject duplicate active source rows (even identical ones) and blank source/target codes with actionable diagnostics before joining; never allow duplicate mapping rows to reweight cover. Aggregate by `(PlotNumber, Layer, resulting species code)` and cap each non-null sum at 99 *after* that aggregation, as `V7mdlLumping.LumpVegData` does (`V7mdlLumping.txt:64-74`). Null-only cover groups remain missing, while a non-null zero remains zero; do not use the retired helper's `sum(..., na.rm = TRUE)` behavior that turns all-missing groups into zero. Metadata lookup follows the resulting species code; unresolved lump-target metadata follows the same conflict/missing rules. The bundled `Sample_Lump` is a useful clean fixture, not proof that arbitrary Access lump tables have unique mappings. `CombineSpp()` is a separate variant-consolidation path, not automatically part of short-report lumping. Any uncapped alternative would need a separately named, reviewed mode rather than silently changing this opt-in rule. Validate numeric results on controlled fixtures before claiming full Access report parity.

**Layer/strata oracle boundary (2026-09-23).** A disposable Access DAO scratch fixture confirmed non-null layer expansion (including zero and `5a`–`5c`), A/B fallback sums capped at 99 but uncapped non-null authoritative totals, suppression of nonpositive A/B rows, and non-null C/D rows including zero. All 33 produced rows matched the copied Access `LayerCode.Layer1234567` reference; none matched the lifeform branch's `LayerCode.LayerCode` key (padded codes like `01`/`06`). This exposes a legacy join mismatch for the tested fixture, not proof of full report output. The package should use a validated, versioned mapping with documented normalized-key behavior for layer and strata, and explicitly mark any lifeform correction as a modernization. Do not treat `LayerCode.Lifeform` text as the species LifeForm grouping metadata. Reproducible runner, results, and limits: `SHORT_VEG_LAYER_STRATA_ORACLE.md` and `data-raw/oracle/short-veg-layer-strata-oracle.json`.

**Suggested staged delivery.** First provide an explicitly non-parity SU-scoped long data API with selected membership, consolidated per-plot cover fields, unpivoted layers, unit labels and diagnostics; then independently verify aggregation and display modes against controlled Access output. Only after that should a standalone QMD replace the retired helper calls and the application reporting UI be rewired.
