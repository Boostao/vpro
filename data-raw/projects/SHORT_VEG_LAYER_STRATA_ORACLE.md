Date: 2026-09-23. Canonical source: `../VPRO_ACCESS/VPro64_forAI/Modules/V7mdlTableConversions.txt` (`ConvertProVeg2V2`: lines 29–97), `V7mdlCreateTables.txt` (`BuildStrataTable`: lines 291–369), `V7mdlReportsShortVeg.txt` (`BuildDataTable`: lines 1509–1525; `MakeSvQueries`: lines 1403–1409), and `../VPRO_ACCESS/VPro64_forAI/Tables_Data/LayerCode.csv`. Reproduce with `data-raw/oracle/run-short-veg-layer-strata-probe.ps1` on the Windows Access VM; retained observed results: `data-raw/oracle/short-veg-layer-strata-oracle.json`.

The runner copies the entire front-end directory into a uniquely named Windows temporary directory, checks the copied front-end hash, runs hidden Access DAO with scratch tables **only in the copy**, reads the copied front end's `LayerCode`, and checks that the original front-end hash is unchanged afterwards. It reconstructs the relevant SQL stages; it does **not** call the VBA functions, exercise form/registry selection, run a complete `NewShortVeg` report, validate actual project data, or claim Excel parity. All seven recorded checks passed; the disposable conversion had 23 rows and the strata transformation 10 rows. The original front-end SHA-256 was unchanged (`01481B94569C7172F32A812E65365F78CEA5E440DD63220D91A37DADE5778423`).

| Stage | Observed DAO behavior on disposable scratch fixture |
| --- | --- |
| Layer conversion | Non-null `Cover{LayerText}` yields a row with that layer (including non-null zero). Nulls do not yield rows. The tested `5a`, `5b`, and `5c` values each became separate rows. |
| Strata A/B | A uses `TotalA` if present, otherwise `Cover1`–`Cover3` summed with nulls as zero and capped at 99; B similarly uses `TotalB` or `Cover4`, `Cover5`, `Cover5a`–`Cover5c` fallback capped at 99. Only positive results yield A/B rows. An authoritative total of 120 or 123 is **not** capped by the fallback rule; an authoritative zero suppresses the row. |
| Strata C/D | Non-null `Cover6`/`Cover7` yields a row at layer `6`/`7`, including zero; null suppresses the row. |
| Reference join | All 33 observed layer/strata rows joined to the copied `LayerCode.Layer1234567` key. None joined to `LayerCode.LayerCode`, whose keys are padded values such as `01`/`06` (and `05a` instead of `5a`). The `GroupAndOrder = 13` lifeform SQL uses the latter key; the fixture exposes a join-key mismatch, **not** a complete lifeform-report result. |

This is a bounded confirmation of the reconstructed SQL and mapping data, not approval of a package mapping equivalent. In particular, `BuildStrataTable` uses `First()` per plot/species; the fixture intentionally has one row per key and does not establish results when duplicate source rows differ. `CreateTempVeg` may consolidate those rows upstream, but this was not tested as an end-to-end report. `ConvertProVeg2V2Null` (the no-layer grouping) is a distinct path and was not probed. The bounded package layer-data API now ships a validated runtime copy of the isolated versioned SQLite artifact (`SHORT_VEG_LAYER_MAPPING_DESIGN.md`). It joins `Layer1234567` intentionally rather than the padded lifeform key; it does not claim Access output parity, compute summary strata totals, or infer lifeforms/taxonomy.
