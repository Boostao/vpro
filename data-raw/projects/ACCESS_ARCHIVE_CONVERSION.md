# Access-to-SQLite archive and VP08 promotion

`vpro_access_inspect(path)` inventories local Access tables, row counts, descriptions, and linked-table names without writing output. `vpro_access_archive(path, archive_path)` copies every readable local table to a separate staging SQLite database, retaining names, columns, nulls, rows, table descriptions (`_table_metadata`), an extraction manifest, source checksum, SQLite column types, and a linked-table-name list. It checks each round trip and removes staging on failure; output must not exist. Forms, VBA, Access query definitions, relationships and linked backend contents are **not** converted. A result is an **archive**, not a certified VP08 project.

`vpro_access_promote_vp08(archive_path, project, target_path)` is an opt-in gate for exactly matching eight-table VP08 families. It checks the Env Access description, manifest hashes and canonical field order; it builds the canonical Sample schema, indexes and constraints into a different file, copies data, checks values, foreign keys and SQLite integrity, and tests package VP08 inspection. It refuses extra core fields, missing fields, mixed schemas and older versions without modifying the archive. Ancillary tables and source-only fields are preserved in the archive, **not** dropped: no promotion file is created if those core fields cannot safely fit the canonical project. No `NewProject` audit event is added to imported history.

The installed `mdbr` 0.3.1 `dbFetch()` returns the first rows again on successive calls, and `mdb_export()` materializes a complete table. This importer therefore reads complete tables under a default limit of 100,000 rows per table, rejects source files over 1 GB before reading, and rejects an extracted R table over 200 MB before copying it to SQLite. The byte limits are configurable; **neither limits peak memory during `mdbr` extraction**, and row count does not predict width. It fails instead of claiming streaming support and does not yet support safe large-file migrations or binary/precision types that do not survive the SQLite round-trip. Archival column types are derived from mdbr R values; Access field sizes, defaults, primary keys and relationships are not claimed as fully represented in the archive. Datetimes are stored as UTC text and require careful source timezone review where local-time semantics matter. Fingerprints are MD5 of serialized SQLite table values for diagnostic integrity, not a cryptographic authenticity proof.

The installed `mdbr` 0.3.1 DBI result holds a full table in memory, and repeated `dbFetch(n = 2)` returned the same first two rows on `Sample_Veg`: chunking `dbFetch()` is not a valid extraction strategy. This fixture includes OLE fields in `Sample_Herbarium`, `USysHerbarium`, and `USysPictureBlob`, but its observed `Sample_Herbarium.Photo` values were all null and `USysPictureBlob` was empty; it does not validate preservation of populated OLE data. The automated disposable-source integration fixture is `../VPRO_ACCESS/VPro64/VPro64.accdb`; tests skip if absent. For other sources, prefer a controlled copy and retain the original alongside the archive and manifest. Do not automatically promote VP02–VP07, unknown or mixed-tag projects: the Access importers have differing table coverage and no lossless policy. Deferred terrain narrowing, succession copying and vegetation optimization are not part of conversion.

Example noninteractive use:

```r
inventory <- vpro_access_inspect("path/to/source.accdb")
receipt <- vpro_access_archive("path/to/source.accdb", "path/to/archive.db")
vpro_access_promote_vp08("path/to/archive.db", "MyProject", "path/to/MyProject.db")
```
