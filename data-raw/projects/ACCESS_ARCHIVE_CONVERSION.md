# Access-to-SQLite archive and VP08 promotion

`vpro_access_inspect(path)` inventories local Access tables, row counts, descriptions, and linked-table names without writing output. `vpro_access_archive(path, archive_path)` copies every readable local table to a separate staging SQLite database, retaining names, columns, nulls, rows, table descriptions (`_table_metadata`), an extraction manifest, source checksum, SQLite column types, and a linked-table-name list. It checks each round trip and removes staging on failure; output must not exist. Forms, VBA, Access query definitions, relationships and linked backend contents are **not** converted. A result is an **archive**, not a certified VP08 project.

`vpro_access_promote_vp08(archive_path, project, target_path)` is an opt-in gate for exactly matching eight-table VP08 families. It checks the Env Access description, manifest hashes and canonical field order; it builds the canonical Sample schema, indexes and constraints into a different file, copies data, checks values, foreign keys and SQLite integrity, and tests package VP08 inspection. It refuses extra core fields, missing fields, mixed schemas and older versions without modifying the archive. Ancillary tables and source-only fields are preserved in the archive, **not** dropped: no promotion file is created if those core fields cannot safely fit the canonical project. No `NewProject` audit event is added to imported history.

`mdbr` 0.3.2 or newer provides `mdb_stream_table()` with an advancing cursor. The importer fetches 1,000 rows at a time by default, verifies each inserted batch against SQLite, and checks the final row count; the per-table row and source-size caps now default to `Inf`. A configurable 200 MB per-batch R size limit is checked **after** each fetch: it cannot bound allocation inside `mdbr`, and row count does not predict row width. Choose a smaller `batch_rows` for exceptionally wide tables. VP08 promotion likewise validates chunked manifest fingerprints and compares sorted value batches without whole-table reads; sorting may use disk-backed SQLite temporary storage. Binary/precision types that do not survive the SQLite round-trip still fail safely. Archival column types are derived from mdbr R values; Access field sizes, defaults, primary keys and relationships are not claimed as fully represented. Datetimes are stored as UTC text and require source timezone review where local-time semantics matter. Fingerprints are MD5 of serialized, ordered SQLite batches (batch size 1,000) for diagnostic integrity, not cryptographic authenticity; archives created by the earlier whole-table fingerprint format must be promoted with their corresponding earlier implementation.

The older `mdbr` 0.3.1 generic DBI result repeated the first rows on `Sample_Veg`; do not substitute `dbSendQuery()` for the new explicit `mdb_stream_table()` cursor. The 0.3.2.9000 cursor was observed to advance across distinct vegetation IDs. The integration fixture includes OLE fields in `Sample_Herbarium`, `USysHerbarium`, and `USysPictureBlob`, but its observed `Sample_Herbarium.Photo` values were all null and `USysPictureBlob` was empty; it does not validate preservation of populated OLE data. The automated disposable-source integration fixture is `../VPRO_ACCESS/VPro64/VPro64.accdb`; tests skip if absent. For other sources, prefer a controlled copy and retain the original alongside the archive and manifest. Do not automatically promote VP02–VP07, unknown or mixed-tag projects: the Access importers have differing table coverage and no lossless policy. Deferred terrain narrowing, succession copying and vegetation optimization are not part of conversion.

Example noninteractive use:

```r
inventory <- vpro_access_inspect("path/to/source.accdb")
receipt <- vpro_access_archive("path/to/source.accdb", "path/to/archive.db")
vpro_access_promote_vp08("path/to/archive.db", "MyProject", "path/to/MyProject.db")
```
