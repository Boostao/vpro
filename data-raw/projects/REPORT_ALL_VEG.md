# Project-wide USysAllVeg reporting rows

`vpro_report_all_veg(context)` translates the SQL of the saved Access query `Queries/USysAllVeg.txt`, not the saved query's UI Filter property. It unpivots Cover1–7, Cover5a–5c, TotalA and TotalB on the physical active-project Veg table with `UNION` (distinct rows), omits null covers, and returns `PlotNumber`, `MyLayer`, `Species`, and `Cover`. It does not apply the selected SU and does not materialize a query/table or generate Excel. Deterministic result ordering adds plot, species and cover tie-breakers to the source's `ORDER BY mylayer`; SQLite text comparison may not replicate Access collation.

This is **not** the `QuickVeg` scratch table: `V7mdlReportsCommonCode.QuickVegRecords` uses Cover1–9, `UNION ALL`-equivalent inserts, and an SU join. The private `V7mdlReportsCommonCode.QuickSummaryReport` writes a DQY file with a project Env to `USysAllVeg` join, but does not reference its optional `SuTable` in that SQL. The canonical VP08 `Sample_Env` in bundled SQLite has no `AssignedSiteUnit` field, which that legacy query selects; none of the Admin site-unit fields has been established as an equivalent. The separate reviewed VP08 data-query contract in `QUICK_SUMMARY_INVESTIGATION.md` now joins Admin and exposes `UserSiteUnit` as the legacy-labeled value in `vpro_report_quick_summary()`. This function remains only the `USysAllVeg` input row query, not a completed Excel report or a mapping of the original `QuickSummaryReport` procedure.
