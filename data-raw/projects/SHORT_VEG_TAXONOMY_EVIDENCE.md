The third bundled `CAMPHIP` record, *Campylium hispidulum* var. *sommerfeltii*, has `Codetype=S` and is excluded from Access `USysAllSpecies`. It must **not** be interpreted as an additional choice for the species-level `CAMPHIP` conflict. [GBIF](https://api.gbif.org/v1/species/11065640) treats *Campylophyllopsis sommerfeltii* as a distinct accepted species; a reviewer should check the VLists code assignment independently if that variety matters. The external databases' taxonomic treatments and access dates can change; no specimen determinations were verified here.

`Codetype=U` is described as “valid code and name” in the bundled species attribute descriptions; `XX` has no documented meaning there. `Report` reflects VLists usage, not a general taxonomic authority. The source candidate table and its fingerprints are described in `SHORT_VEG_SPECIES_METADATA_REVIEW.md`; do not edit that generated CSV to approve either choice. Any future override should capture the precise observed candidate tuple, reviewer identity, date, justification, source fingerprints, and external references; a new name absent from candidates requires a separate, explicit versioned enrichment policy, not a fabricated tuple.
