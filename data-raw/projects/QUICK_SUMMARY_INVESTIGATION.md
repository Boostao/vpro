# VP08 Quick Summary investigation

`V7mdlReportsCommonCode.QuickSummaryReport` (SaveAsText lines 34–90) is a private VBA function that writes a legacy `Excel01.dqy` text file. Its SQL (lines 71–74) selects `<project>_Env.AssignedSiteUnit` and joins Env to `USysAllVeg` by plot; its optional `SuTable` is read but never used in the SQL. The saved `Queries/USysAllVeg.txt` SQL uses `UNION` over non-null Cover1–7, Cover5a–5c, TotalA and TotalB. VP05 import maps historical Env `AssignedSiteUnit` into `UserSiteUnit` (`V7mdlImportVProVer05`, lines 20–25); the later VP06 import places `UserSiteUnit` in Admin (`V7mdlImportVProVer06`, lines 42–49). Current VP08 `Sample_Admin` defines `UserSiteUnit` separately from `BECSiteUnit`; `Sample_Env` lacks `AssignedSiteUnit`.

The reproducible VM script is `data-raw/oracle/run-quick-summary-probe.ps1`; retained output is `data-raw/oracle/quick-summary-vp08-oracle.json`. The script copies the full `VPro64` directory to a timestamped local temporary folder, checks the source front-end SHA-256 before/after and initial copy hash, opens only the copy in Access 16 COM, and runs the **original DQY SELECT text adapted only to DAO syntax** against `Sample_Env` and the saved `USysAllVeg` query. DAO fails with `Too few parameters. Expected 1.`; the copy's Env does not have `AssignedSiteUnit`. A test rewrite using `Sample_Admin.UserSiteUnit` and explicit Env–Admin–AllVeg joins opens and yields 2,026 rows with either inner or left Admin join on this Sample. The copied front end remained locked to the hashing process at shutdown, so no after-copy hash was recorded; the source hash was unchanged.

**Boundary:** The private QuickSummaryReport function itself was not invoked. Its DQY references a legacy Access 97 DSN and `VPro97.mdb` (absent in the copied directory); no DQY file was refreshed through Excel. DAO's missing-field error therefore confirms failure of the query text against a VP08 Access front end, not the exact user-visible error from Excel or whether the private file-writing routine completes. Access may resolve an unrecognized name as a parameter, hence the DAO wording.

**Reviewed VP08 data contract:** `data-raw/projects/QUICK_SUMMARY_VP08.sql` is the reference design; `vpro_report_quick_summary(context)` implements it using the same `USysAllVeg` union builder as `vpro_report_all_veg()`. It requires an active VP08 project, keeps the original project-wide Env–`USysAllVeg` inner join, and adds an explicit **left** Admin join on `Admin.Plot = Env.PlotNumber`. `Admin.UserSiteUnit AS AssignedSiteUnit` is a deliberate field-successor mapping based on the VP05/VP06 import lineage, not a renamed physical Env field. The left join preserves Env-plus-vegetation rows if Admin is missing: a disposable SQLite Sample copy with one Admin row removed retained all 2,026 rows, including nine rows for that plot with a null label. The intact canonical Sample returns 2,026 rows, 52 plots and no null unit labels. The report returns five typed columns in deterministic layer/plot/species/cover order. It does not join the current SU, substitute `BECSiteUnit` or `Sample_SU.SiteUnit`, generate DQY/Excel output, or claim parity of the original private routine. SQLite collation and type representation may differ from Access. This review approves only the data-query modernization; no reviewed parity override is claimed for the complete QuickSummaryReport procedure. A standalone HTML presentation of the reviewed data lives at `inst/reports/quick_summary.qmd` and is render-tested separately from the legacy reporting UI; it does not restore DQY/Excel behavior.
